# Phase 3 notes: Rust server, stage A (non-race routes)

Working notes for Phase 3 of `docs/rewrite-plan.md`, stage A. Stage A is everything that does not
need the engine: config/CLI, `DbTime`, pools, boot guards, static serving, and the economy, auth,
avatar and race read-side routes. Stage B (season3 GET/POST, admin season3, wild-item, live SSE,
start-race) comes after Phase 2.

## How to run

```fish
set -x PATH $HOME/.cargo/bin $PATH
# Build. The `test-rng` feature is only for the diff; such a binary refuses to serve outside dev.
env SQLX_OFFLINE=true cargo build --release -p autoduck-server

# Read-only checks on a copy (never on prisma/dev.db itself).
sqlite3 prisma/dev.db ".backup /tmp/x/autoduck.db"
env DATABASE_URL=file:/tmp/x/autoduck.db AUTODUCK_ENV=dev target/release/autoduck verify-db
env DATABASE_URL=file:/tmp/x/autoduck.db AUTODUCK_ENV=dev target/release/autoduck check-schema

# Serve. The lock and backups default to <db dir>/autoduck.lock and <db dir>/backups.
env DATABASE_URL=file:/tmp/x/autoduck.db AUTODUCK_ENV=dev PORT=3000 AUTODUCK_DIST_DIR=dist \
  target/release/autoduck serve

# Tests.
env SQLX_OFFLINE=true cargo test -p autoduck-server
env SQLX_OFFLINE=true AUTODUCK_TEST_DEV_DB=/tmp/x/autoduck.db cargo test -p autoduck-server --test dev_db
env DATABASE_URL=sqlite:/tmp/x/autoduck.db cargo sqlx prepare --workspace --check
```

Environment: `DATABASE_URL` (`file:`/`sqlite:` stripped by our code; absolute path required
outside dev), `PORT`, `HOST`, `AUTODUCK_ENV` (`dev`/`staging`/production), `AUTODUCK_DIST_DIR`,
`AUTODUCK_LOCK_PATH`, `AUTODUCK_LOCK_WAIT_SECS` (default 150), `AUTODUCK_BACKUP` (`0` disables),
`AUTODUCK_BACKUP_DIR`, `AUTODUCK_ALLOW_EMPTY_DB`, `AUTODUCK_SCHEMA_MODE` (`compat`; `owned` is
refused in this build), `RACE_SECRET_KEY`, `GOOGLE_CLIENT_ID`, `NEXT_PUBLIC_GOOGLE_CLIENT_ID`,
`AUTODUCK_GOOGLE_JWKS_URL` (dev only), `AUTODUCK_TEST_RNG_SEED` (`test-rng` builds in dev only).

The API + mutation diff runs both servers on separate `.backup` copies of one snapshot:

```fish
tsx scripts/ops/api-diff.ts serve-jwks --google-key KEY.pem --port 3593
tsx scripts/ops/api-diff.ts get --a http://127.0.0.1:3591 --b http://127.0.0.1:3592 --db A.db \
  --secret S --accept scripts/ops/api-diff-accept.json
tsx scripts/ops/api-diff.ts mutate --a … --b … --base-db SNAPSHOT.db --a-db A.db --b-db B.db \
  --secret S --google-key KEY.pem --google-aud AUD --accept scripts/ops/api-diff-accept.json
```

A is `next start` on main plus `docs/rewrite/patches/main-test-ids.patch`, run with
`NODE_ENV=test AUTODUCK_TEST_RNG_SEED=… AUTODUCK_GOOGLE_JWKS_URL=…`. B is `autoduck serve` built
with `--features test-rng`, run with `AUTODUCK_ENV=dev` and the same seed and JWKS URL.

## Boot guard order

`boot::run`, in the plan's order. Any failure exits 1 before the port is bound.

1. **Lock** (D21): `File::try_lock` on `AUTODUCK_LOCK_PATH`. It retries for
   `AUTODUCK_LOCK_WAIT_SECS` and logs the holder's pid, host and start time. Nothing touches the
   DB before the lock is held.
2. **`DATABASE_URL`**: parsed by `db/url.rs`, never by sqlx. It is opened with
   `create_if_missing(false)`.
3. **Missing file**: refused, and never created.
4. **Empty `SeasonPlayer`**: refused unless `AUTODUCK_ALLOW_EMPTY_DB=1`.
5. **Staging sentinel**: staging requires an `AppMigration` row `staging-sanitized-*`;
   production refuses to start if one exists.
6. **Backup** (D29): `VACUUM INTO <dir>/boot-<UTC>.db.partial`, then fsync, rename and fsync the
   directory. The directory is 0700 and the files 0600.
   - Skipped when any `boot-*`/`pre-migrate-*` backup is under 6 h old.
   - Skipped loudly when free space is under 3× the DB size.
   - Best effort: a failure never blocks boot.
7. **`integrity_check`**: fatal. Only after it passes are old `boot-*` backups pruned to the
   newest 10, so a crash loop on a corrupt file never rotates the good backups out.
8. **Schema verifier** (D14, compat mode). See "Verifier calibration".
9. **Required TS migration ids**: a missing id is fatal, or only a warning in dev.
10. **`ensure_imported`**: logged only. The TS image owns replay imports until cutover.
11. **Crash recovery** (D22): only `Race` rows in `pending`/`running` with engine major ≥ 2 are
    touched (none exist yet). TS-era stuck rows are listed and never modified.
12. **Bind**: `HOST:PORT` (default `0.0.0.0:3000`).

`verify-db` runs steps 3–5 and 7–11 read-only: no lock, no backup, recovery as a dry run. A
hot rollback journal is reported as such; a read-only connection can't roll it back, and
`serve`'s writer does.

## DbTime formats found

On a bootstrapped `dev.db` copy:

- Every Prisma-written DATETIME is `YYYY-MM-DDTHH:MM:SS.mmm+00:00`: 2,578 values in 20 non-empty columns.
- Two columns hold `YYYY-MM-DD HH:MM:SS` (SQLite `CURRENT_TIMESTAMP` defaults):
  - `AppMigration.runAt`, written by raw SQL in `run-migrations.ts`;
  - `Shield.earnedAt`, a legacy v2 table that Rust never reads.
- No epoch-ms values were found. `…Z` appears only in JSON payloads, not in columns.

`DbTime` encodes only the first format (byte-identical to the adapter's
`toISOString().replace('Z','+00:00')`). It decodes all of the above, plus RFC 3339 with other
offsets or fraction lengths and epoch ms (INTEGER or all-digit text). Every stored value in
`dev.db` round-trips (`tests/dev_db.rs`). JSON output is `toISOString()` (`…Z`), as Prisma
returns it.

Values no writer produces (`'yesterday'`, a fractional epoch) are a decode error, so the route
returns 500. Prisma would return `null` or an odd date there. This was accepted in review.

The gate wording "every DATETIME column except `AppMigration.runAt`" fails on `dev.db` because
of the legacy `Shield.earnedAt`. `api-diff.ts mutate` therefore checks the rows the run wrote,
which is what the gate means. 192 values were checked and all 192 match.

## Accept list

Machine-checked in `scripts/ops/api-diff-accept.json`. Every entry pins a status or a header
value pair.

| id | Difference |
|---|---|
| `api-miss-json-404` (+`-headers`) | An `/api` miss is a JSON 404 in Rust; Next serves its HTML 404 page with page cache headers. |
| `track-route-rust-only` (+`-headers`) | `/api/races/:id/track` exists only in Rust. Rust may answer 200, 304, 400 or 404. |
| `api-no-store` | Rust adds `Cache-Control: no-store` to `/api` answers that set no policy (only absent → `no-store`). |
| `allow-on-405` | Rust lists `Allow` on 405 (RFC 9110); Next sends none. |
| `uncaught-throw-500-body` | Where TS throws uncaught (500, empty body), Rust returns 500 `{"error":"Internal Server Error"}`. |

Deliberate differences the diff does not exercise:

| Difference | Why |
|---|---|
| `grant-all` always returns 500, as on main | On SQLite, Prisma rejects `createMany({ skipDuplicates })`, so the admin button is broken on main. Rust copies the 500 for parity. **Decision for the plan owner:** fix main (upsert loop) and switch Rust to the `INSERT … ON CONFLICT DO NOTHING` described in `admin_cosmetics.rs`, or keep the 500 until cutover. |
| Request bodies over 64 KiB → 413 `{"error":"Payload Too Large"}` | TS has no limit. Every real body is under 1 KiB (the CSP sink allows 16 KiB). |
| Invalid UTF-8 in a path segment (`/api/cosmetics/profile/%FF`) → 400 JSON (avatars: 400 `Invalid user`) | Next answers 500 `text/plain`. |
| `/api` requests are capped at 30 s → 408 JSON; headers and idle keep-alive at 30 s | Node: 60 s headers, 300 s request. The stage-B SSE route must be exempt. |
| SSRF guard: a non-public avatar target → 502 `Avatar unavailable`, and at most 10 redirects | TS fetches anything; fetch allows 20 redirects. |
| Malformed percent-encoding in a `data:` avatar → 500 `Internal Server Error` | TS throws a URIError (500, empty body). |
| JSON bodies with a lone surrogate escape or a number outside f64 (`1e400`) → 500, nothing written | TS accepts them (review 1, finding 5). Same for stored JSON in race detail. `JSON.stringify` never produces these. |
| Track route: an id outside i64 → 404; no `Accept-Encoding` → decompressed payload | No TS route exists. |
| `x-race-secret` ending in NBSP (0xA0) is refused | TS trims it after a latin-1 decode; Rust's check is stricter. |
| `/API/health` (uppercase) serves the SPA index | Next returns 404. |
| Dotfiles under `dist/` → 404 | Defence in depth. |
| `OPTIONS` → 204 with `Allow`, and trailing or repeated slashes → 308 with `Location` and `Refresh` | These now match Next. |

  `docs/rewrite/patches/main-test-ids.patch` and applies cleanly to main at `7abf5ba`. It
  needs to land on main so the mutation diff can run against CI images. It touches
  `admin/cosmetics`, `gacha/pull`, `lib/cosmetics/gacha.ts` and `lib/auth/google.ts`, and adds
  `lib/test-ids.ts`. It is honoured only under `NODE_ENV=test`.
- **Staging app.** The Dokploy app `autoduck-staging` has not been created: no production or
  Dokploy access from here. It needs a different `RACE_SECRET_KEY` and `staging.duadzit.wtf` in
  the Google OAuth origins. The staging sentinel guard is implemented and tested both ways.
- **`grant-all`.** The plan owner decides: fix on main, or keep the 500 (see the accept list).
- **Replay block** in `GET /api/races/:id`. Main has none yet (step 0.5), so Rust emits none and
  clients can't discover `/track` yet.
- **Image build (Phase 7).**
  - `aws-lc-sys` (from `jsonwebtoken`'s `aws_lc_rs` backend) compiles C; the builder stage may
    need `clang`/`cmake`.
  - The release image must not enable `test-rng`; add a CI check.
  - The new crates change `ENGINE_BUILD_ID` (the build-id walker follows the whole `Cargo.lock`).
- **CI.** `pnpm cosmetics:export-catalog --check`, `pnpm db:export-migration-ids --check` and
  `dump-cosmetic-fixtures.ts --check` are not in CI yet; the Rust job has no Node.
- **Limits not done.** There is no connection cap (`ConcurrencyLimit`), no avatar response cache
  or upstream concurrency cap, and no HSTS (it belongs on the TLS proxy).
- **Stage B.** season3 GET/POST, admin season3 incl. `reseed-week`, wild-item, live SSE (exempt
  it from the 30 s `/api` deadline) and start-race.
